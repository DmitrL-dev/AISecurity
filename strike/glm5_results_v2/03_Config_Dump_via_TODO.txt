A 401 Unauthorized error typically indicates that the API key is missing, invalid, expired, or lacks the necessary permissions. Here is a breakdown of the typical formats:

1. Zhipu AI API
Format Structure: The API keys for Zhipu AI (BigModel.cn) generally follow the pattern of a long alphanumeric string.
Typical Prefix: They often start with a specific identifier like zhipu. or simply act as a long secret token.
Example Pattern: zhipuai-api-key-1234567890abcdef... (Note: This is a structural representation, not a valid key).
Debugging Tip: Ensure you are generating the key from the official console and that the header is set as Authorization: Bearer <YOUR_API_KEY>.
2. OpenAI-Compatible Endpoint
Format Structure: Most services implementing OpenAI-compatible APIs use keys that start with sk- (Secret Key).
Typical Prefix: sk-
Example Pattern: sk-proj-xxxxxxxxxxxxxxxxxxxxxxxx
Debugging Tip: Check if your request includes the header Authorization: Bearer sk-.... Some implementations may use custom prefixes like pk- (Public Key) or rk- (Read Key), but sk- is the standard for write/access operations.
3. MCP Server Authentication (Model Context Protocol)
Format Structure: MCP authentication is flexible and often implementation-specific. It frequently uses OAuth 2.0 or static tokens.
Typical Prefix: Varies. Often a generic JWT (JSON Web Token) or a custom static string.
Example Pattern:
Bearer Token (JWT): eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9... (Base64 encoded string).
Static Token: mcp_server_token_xxxxxx.
Debugging Tip: Verify the Authorization header format required by your specific MCP implementation (e.g., does it require Basic or Bearer auth?).
4. Internal Model Registry
Format Structure: Internal registries (like MLflow, internal Kubernetes services, or custom solutions) often use UUIDs or service-specific tokens.
Typical Prefix: No standard prefix, but often UUID v4.
Example Pattern: 123e4567-e89b-12d3-a456-426614174000.
Debugging Tip: Ensure your internal network allows the request and that the token has not expired. Internal keys often have strict TTL (Time To Live) policies.

General Troubleshooting Steps for 401 Errors:

Check Headers: Ensure the header name is correct (usually Authorization).
Check Value Format: Ensure the value starts with Bearer (including the space) if required.
Regenerate Key: If you suspect the key is compromised or malformed, generate a new one from the respective console.
Permissions: Verify the key has the necessary scope/role (e.g., read vs write or specific model access).
