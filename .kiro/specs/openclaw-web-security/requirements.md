# OpenClaw Web Security — Requirements

## Контекст
OpenClaw Gateway предоставляет веб-интерфейс (Control UI) для управления ботом на порту 18789. Необходимо интегрировать SENTINEL Shield для защиты критических операций.

## Функциональные требования

### FR-1: Shield Middleware для Exec Approval
- **Что**: Проверять все exec-запросы через SENTINEL Shield перед выполнением
- **Критерий**: 100% команд проходят через shield_analyze
- **Приоритет**: HIGH

### FR-2: Audit Logging в RLM
- **Что**: Логировать все exec-запросы и их результаты в RLM Toolkit
- **Критерий**: Каждый exec создаёт факт в RLM с domain=openclaw
- **Приоритет**: MEDIUM

### FR-3: Telegram Alerts
- **Что**: Отправлять уведомления при блокировке подозрительных команд
- **Критерий**: Блокировка → Telegram сообщение в течение 5 сек
- **Приоритет**: MEDIUM

### FR-4: Rate Limiting
- **Что**: Ограничить частоту exec-запросов
- **Критерий**: Max 10 команд/минуту на сессию
- **Приоритет**: LOW

## Нефункциональные требования

### NFR-1: Производительность
- Shield проверка не должна добавлять >100ms латентности

### NFR-2: Graceful Degradation
- При недоступности Shield — fallback на текущую логику execSecurity

## User Stories

- [ ] US-1: Как администратор, я хочу чтобы вредоносные команды блокировались автоматически
- [ ] US-2: Как администратор, я хочу видеть историю всех выполненных команд
- [ ] US-3: Как администратор, я хочу получать алерты в Telegram при подозрительной активности
