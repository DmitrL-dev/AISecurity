# Guard Lab implementation plan

**Goal:** Ship a reviewable, locally usable input-evaluation package on the
existing public AISecurity core, with accurate error and metric accounting.

**Architecture:** Python standard-library loader/metrics/CLI; resource-limited
native subprocess; immutable public dependency. No private source export.

**Tech stack:** Python 3.11, setuptools, unittest, public PyO3/Rust dependency.

**Spec:** `docs/superpowers/specs/2026-09-08-guard-lab-design.md`.

**Global constraints:** Tests/builds on an owned VPS only; one build worker with
memory limits. No credentials in output, no engine changes, no new hosted path,
no production mutation. Execute inline to limit agent usage.

- [x] Verify public HEAD/tree and binding API; establish isolated source branch.
- [x] Identify ambient signature discovery and separate credential allegation.
- [x] Baseline native build in a disposable VPS workspace.
- [x] RED: loader/path/dedup/metrics/privacy/error tests against absent package.
- [x] GREEN: bounded loader and content-free metrics/report implementation.
- [x] RED/GREEN: native dependency provenance, process deadlines, malformed and
  failed native output, actual demo through installed CLI.
- [x] Package and document the one supported install path. Keep legacy scope
  clearly separate; add new-package license and provenance notices.
- [x] Run fresh unit/CLI/native installation acceptance and review release
  boundary. The final Linux/Python 3.11 run passed 24 tests, including the real
  native dependency, ambient-signature control and large Unicode input. Tests
  ran with the container network disabled; no detector source was changed.

Before publication, check the final archive's exact file membership and secrets,
then commit only allowlisted files and open a topic-branch PR. Record those
receipts in the PR. Do not merge, tag or announce a release as part of this plan.

VPS unit command (from package directory):
`python -m unittest discover -s tests -v`.
Installed acceptance command: `guard-lab --demo`.
Negative acceptance: malformed input exits 2 with a fixed error code; missing or
failed native binding produces execution errors and exits 1, never success.
