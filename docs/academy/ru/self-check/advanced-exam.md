## Раздел 1: Продвинутая детекция (20 вопросов)

### Q1. Что такое Topological Data Analysis (TDA) в AI security?

- A) Сканирование сетевой топологии
- B) Математический анализ формы данных для детекции аномалий
- C) Оптимизация запросов к базе данных
- D) Мониторинг оборудования

<details>
<summary>Ответ</summary>

**B) Математический анализ формы данных для детекции аномалий**

TDA использует persistent homology для анализа «формы» эмбеддингов промптов, детектируя атаки, которые меняют топологическую структуру.

</details>

---

### Q2. Что измеряет «persistent homology»?

- A) Персистентность памяти
- B) Топологические признаки, сохраняющиеся на разных масштабах
- C) Консистентность базы данных
- D) Сетевую латентность

<details>
<summary>Ответ</summary>

**B) Топологические признаки, сохраняющиеся на разных масштабах**

Persistent homology идентифицирует связные компоненты, петли и пустоты в данных, которые остаются стабильными при разных разрешениях.

</details>

---

### Q3. Какое число Бетти представляет связные компоненты?

- A) β₀
- B) β₁
- C) β₂
- D) β₃

<details>
<summary>Ответ</summary>

**A) β₀**

β₀ считает связные компоненты, β₁ считает петли/дыры, β₂ считает пустоты.

</details>

---

### Q4. Что такое Crescendo атака?

- A) Единичная большая инъекция
- B) Постепенная многоходовая эскалация
- C) Base64 закодированная атака
- D) Переключение ролевой персоны

<details>
<summary>Ответ</summary>

**B) Постепенная многоходовая эскалация**

Crescendo атаки медленно эскалируют по ходам разговора, обходя single-turn детекцию.

</details>

### Q5. Как SENTINEL детектирует Crescendo атаки?

- A) Pattern matching на сообщение
- B) Session-level поведенческий анализ со скользящим окном
- C) Только фильтрация вывода

<details>
<summary>Ответ</summary>

Отслеживание risk scores по нескольким ходам для детекции паттернов постепенной эскалации.

</details>

## Раздел 2: Red Teaming (20 вопросов)

### Q6. Какова основная цель red teaming LLM?

- A) Улучшить качество ответов
- B) Идентифицировать уязвимости до атакующих
- C) Снизить API costs
- D) Увеличить throughput

<details>
<summary>Ответ</summary>

**B) Идентифицировать уязвимости до атакующих**

Red teaming проактивно обнаруживает слабости для их исправления до эксплуатации.

</details>

---

### Q7. Какая техника обходит English-only pattern detection?

- A) Base64 кодирование
- B) Мультиязычные атаки (русский, китайский и т.д.)
- C) Более длинные промпты
- D) Более быстрые запросы

<details>
<summary>Ответ</summary>

**B) Мультиязычные атаки (русский, китайский и т.д.)**

Pattern-based детекция часто не работает на не-английском тексте, позволяя language-switching обходы.

</details>

---

### Q8. Что такое «prompt chaining» в атаках?

- A) Использование нескольких API вызовов
- B) Разбиение вредоносных инструкций на несколько сообщений
- C) Кэширование ответов
- D) Балансировка нагрузки

<details>
<summary>Ответ</summary>

**B) Разбиение вредоносных инструкций на несколько сообщений**

Атакующие разделяют payload'ы по ходам, чтобы избежать детекции на уровне сообщения.

</details>

---

### Q9. Как тестировать на indirect injection уязвимости?

- A) Отправить прямые тестовые промпты
- B) Инжектировать payload'ы в документы/URL которые RAG система получает
- C) Увеличить temperature
- D) Использовать больший контекст

<details>
<summary>Ответ</summary>

**B) Инжектировать payload'ы в документы/URL которые RAG система получает**

Тестировать путём подсаживания вредоносного контента в источники данных, которые система потребляет.

</details>

---

### Q10. Какая метрика инструментов показывает эффективность red team?

- A) API латентность
- B) Bypass rate (успешные атаки / всего попыток)
- C) Длина ответа
- D) Количество токенов

Bypass rate показывает, как часто атаки обходят защиту.

</details>

## Раздел 4: Enterprise Deployment (20 вопросов)

### Q16. Что такое defense-in-depth для LLM приложений?

- A) Единый мощный фильтр
- B) Множественные перекрывающиеся слои безопасности
- C) Deep neural network
- D) Максимальная длина контекста

<details>
<summary>Ответ</summary>

**B) Множественные перекрывающиеся слои безопасности**

Defense-in-depth использует вместе: input validation, behavioral analysis, output filtering и мониторинг.

</details>

---

### Q17. Какой SLI наиболее критичен для production SENTINEL?

- A) Длина ответа
- B) Latency p99 и false positive rate
- C) Размер модели
- D) Количество токенов

<details>
<summary>Ответ</summary>

**B) Latency p99 и false positive rate**

Security scanners должны быть быстрыми (низкая латентность) и точными (низкие false positives/negatives).

</details>

---

### Q18. Как SENTINEL должен интегрироваться с incident response?

- A) Только email алерты

- C) Ручной анализ логов
- D) Еженедельные отчёты

<details>
<summary>Ответ</summary>

**B) SIEM интеграция, автоматические playbooks, пути эскалации**

Enterprise deployment требует автоматического алертинга и response workflows.

</details>

### Q19. Какой рекомендуемый паттерн deployment?

- A) Inline (синхронное сканирование перед LLM)
- B) Только Async (пост-обработка)
- C) Только Batch (ежедневные сканы)
- D) Ручная проверка

<details>

</details>
