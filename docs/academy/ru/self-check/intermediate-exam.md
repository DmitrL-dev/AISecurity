## Раздел 1: Агентная безопасность (15 вопросов)

### Q1. Какая основная проблема безопасности с ReAct агентами?

- A) Потребление памяти
- B) Неконтролируемые цепочки выполнения инструментов
- C) Медленное время ответа
- D) Высокие затраты на API

<details>
<summary>Ответ</summary>

**B) Неконтролируемые цепочки выполнения инструментов**

ReAct агенты могут выполнять несколько инструментов последовательно, и атакующий может манипулировать ими для цепочки опасных вызовов.

</details>

---

### Q2. В паттерне Plan-Execute, где должна происходить валидация безопасности?

- A) Только после выполнения плана
- B) Только перед планированием
- C) На этапе планирования И перед каждым шагом выполнения
- D) Только в финальном выводе

<details>
<summary>Ответ</summary>

**C) На этапе планирования И перед каждым шагом выполнения**

Валидируйте план перед выполнением И каждый шаг при выполнении — эшелонированная защита.

</details>

---

### Q3. Что такое "граница доверия" в мульти-агентных системах?

- A) Лимит памяти агента
- B) Точка где данные перемещаются между разными уровнями доверия
- C) Максимальное количество агентов
- D) Порог латентности

<details>
<summary>Ответ</summary>

**B) Точка где данные перемещаются между разными уровнями доверия**

Границы доверия отмечают переход данных от недоверенного (пользователь, внешний) к доверенному (система, агент) контексту.

</details>

### Q7. Какой правильный порядок порогов SENTINEL scan?

- A) flag < block (напр., flag 0.5, block 0.8)
- B) flag > block
- C) flag = block
- D) Пороги не связаны

<details>
<summary>Ответ</summary>

**A) flag < block (напр., flag 0.5, block 0.8)**

Порог flag должен быть ниже для пограничных случаев; порог block выше для определённых угроз.

</details>

### Q8. Что делает декоратор `guard`?

Декоратор @guard обёртывает LLM вызовы для сканирования запросов и ответов на угрозы.

</details>
